# Java 工程师 AI Agent 7 天学习资料

本资料依据工作区原有《AI Agent 岗位 7 天学习路线》《AI Agent 岗位面试题库（含高频答案）》《适合 Java 工程师的 AI Agent 项目方案》整理，并围绕“小型知识库问答 Agent”补充工程细节。编制日期：2026-10-30。

适用：有 Java 后端经验、刚开始学习 LLM 应用，希望完成入门实践并准备面试的工程师。每天建议投入 3–4 小时；第 6 天首次开发可能需要 5–8 小时，未完成可拆成两天。7 天目标是形成知识框架和可演示的小型闭环，不等于掌握生产级 Agent 平台。

## 项目主线与投入边界

配套设计见 [小型Agent最小闭环系统设计](../小型Agent最小闭环系统设计.md)。第一阶段使用本地 Java 服务、云模型 API、少量 Markdown 知识文件和关键词检索；不需要先买服务器。向量检索作为第 2 天的学习实验和后续升级项，不是首个 Agent 闭环的前置条件。

原路线中的 Python/FastAPI/LangGraph 路径调整为 Java 21 + Spring Boot + 模型 API，LangGraph 先理解图编排思想即可。项目第一个版本为模型能够自主选择只读工具的有限循环；固定检索流程应称为 RAG 工作流。两者都能用于学习，但面试时应按实际实现说明。

## 对原面试材料的必要补充

- 聊天界面也可能有工具和记忆，不能只按是否“会聊天”判断 Agent；观察谁决定下一步动作。
- RAG 能降低部分无依据回答风险，无法保证消除幻觉；检索、生成、引用都要评测。
- 微调也可能影响知识表现，但动态知识维护与逐条授权通常更适合检索方案，两者可以组合。
- Trace 记录可观察的消息类型、工具参数摘要、结果 ID、耗时和错误；不要求获取或保存模型隐藏推理。
- 规划不是每个任务都需要独立调用模型；先用简单流程和硬限制，再讨论复杂编排。
- 面试稿中的所有指标和经历必须换成真实记录，未实现功能明确说“设计中”。

原文保持不变；本资料是扩展学习包，不包含已经实现并运行的应用代码。
