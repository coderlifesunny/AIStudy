# 第1天：LLM 与 Agent 基础

目标：理解今天的机制，并能在小型知识库 Agent 中指出它的落点。

## 1. LLM 在系统中的位置

LLM 根据上下文预测并生成后续 token。它可以生成文本或符合协议的工具调用请求，但不会凭空连接你的数据库。Java 程序负责联网、认证、执行工具和处理失败。将它理解为一个结果有不确定性的远程组件，保留你熟悉的超时、限流和错误处理。

Token 是模型处理文本的单位，不等同于中文字符或英文单词。上下文窗口包含系统提示、历史消息、工具定义、检索结果等输入；输出也受模型上限约束。历史越长，成本和延迟通常越高。

Transformer 的注意力机制让不同位置的表示发生交互，模型从上下文中建立关联。入门阶段应能解释“为什么上下文重要”，不必先推导注意力公式。模型训练形成的参数知识不等于实时、可授权查询的业务数据库。

## 2. Prompt 与推理参数

系统提示规定任务和回答规范，用户消息给出本次目标，工具消息提供外部结果。明确角色、证据边界、输出结构和失败方式，比单纯要求“你是一位专家”更容易验证。

Temperature 和 top-p 影响采样；低 temperature 不能保证事实正确或完全可复现。先使用供应商支持的默认参数或低随机性配置，固定一组参数进行比较。模型不支持某参数时应删掉它，不能照抄其他模型配置。

幻觉指输出缺乏依据或与事实不符。它可能来自模型自身、错误检索、过期文档和问题歧义；不能简单归结为没有 RAG。

## 3. Chat、Workflow、Agent

| 形态 | 谁决定下一步 | 本项目中的例子 |
|---|---|---|
| 直接聊天 | 通常一次生成 | “解释一下 Java 的接口” |
| 固定工作流 | 程序预定步骤 | 每次先检索，再生成 |
| 有限 Agent | 模型在白名单工具中选择动作，代码约束执行 | 模型选择检索主题，读取结果，决定补查或回答 |

ReAct 强调动作与观察交替；Plan-Act 先制定计划再执行。简单知识问答不需要额外的规划模型调用。记录工具选择与结果即可，不依赖获取模型隐藏推理。

## 4. 贯穿案例

用户问“订单服务发布失败怎么回滚？”模型提出 `search_documents(query="订单服务 回滚")`；Java 执行只读检索并返回片段；模型按证据回答；应用校验引用并结束。找不到证据则拒答或要求补充信息。

你应能指出其中两次模型请求、一次本地工具执行，以及程序负责的权限与停止规则。
