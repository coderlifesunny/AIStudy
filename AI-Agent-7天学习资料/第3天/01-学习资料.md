# 第3天：Tool Calling 与有限编排

目标：理解今天的机制，并能在小型知识库 Agent 中指出它的落点。

## 1. 协议的完整往返

应用发送消息和 tools 定义；模型可返回普通文本或 tool_calls；应用校验工具白名单、参数和权限并执行；把原始 assistant 工具调用消息和对应 tool 消息一起追加，再请求模型。工具结果必须通过 tool_call_id 对应原调用，不能当作新的用户指令拼接。

只要工具清单中只有 `search_documents`，工具名由模型选择也仍需要动态决定查询词、是否补查和何时回答。后续可以加受授权限制的 `get_document_excerpt`，无需添加任意代码执行工具。

## 2. 最小 Schema

```json
{"type":"function","function":{"name":"search_documents","description":"检索当前用户有权访问的知识片段；没有匹配返回空数组","parameters":{"type":"object","properties":{"query":{"type":"string","maxLength":200}},"required":["query"],"additionalProperties":false}}}
```

Schema 描述不是安全边界。Java 仍必须检查 query 非空、长度、未知字段和工具名；ownerId、tenantId 由认证上下文注入，不接受模型声明。

## 3. 执行策略

初始限制：最多 2 次工具执行、最多 3 次逻辑模型调用、整个请求 30 秒、每个模型请求最多一次瞬时故障重试。多条工具请求逐一校验和计数，超出剩余工具预算的调用返回 `TOOL_BUDGET_EXCEEDED`，不执行。最终生成调用禁止工具，仍返回工具请求则作为协议错误结束。

重复工具名和相同参数可以复用当前请求内的结果，仍计入模型试图调用的工具预算，防止死循环。业务空结果不算网络失败，也不应该反复重试。

## 4. Java 职责划分

`AgentService` 管循环，`ModelGateway` 管 API 协议与超时，`ToolRegistry` 管白名单与参数，`DocumentSearchTool` 查证据，`AnswerValidator` 查引用，`TraceRecorder` 留执行记录。

Spring AI 能封装工具定义和消息转换，但第一步应看懂原始消息。如果使用框架自动循环，必须确认预算与超时能在每次执行前生效；不要再套一层重复循环。
