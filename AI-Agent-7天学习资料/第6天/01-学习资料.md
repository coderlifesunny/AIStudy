# 第6天：完成最小知识库 Agent

目标：理解今天的机制，并能在小型知识库 Agent 中指出它的落点。

## 1. 今日目标

完成可演示的“用户问题 → 模型选工具 → Java 执行检索 → 工具结果回传 → 模型回答 → 引用校验 → Trace”链路。详细协议、预算和验收以 [配套设计](../../小型Agent最小闭环系统设计.md) 为准。

范围：本机单人、Markdown 知识文件、一个只读工具、普通 HTTP 请求、内存会话和 JSONL 日志。先不做上传平台、前端工程、多 Agent 和服务器采购。

## 2. 建议目录


JDK 21 作为学习基线。框架按实施时兼容矩阵锁定版本；不混用不同大版本教程。原始 HTTP 消息或 Spring AI 均可，但本次学习只选一种实现，默认用 HTTP 客户端显式循环，先看懂协议。

## 3. 联调顺序

先普通 API 调用成功；再伪造工具请求测试分派；再工具真实检索；最后把结果回传模型。每一步失败都要能独立观察，避免一开始一次接好全部组件。

模型最终返回 JSON 包含 answer、citations、refused。应用验证结构、引用范围与证据前置条件；不存在有效证据时采用固定拒答，不让失败路径回退到无依据回答。

## 4. 演示必须覆盖三类情况

成功：按文档回答订单回滚步骤并带来源。

业务拒答：询问知识库没有的工资或业务规则，说明未找到依据。

系统失败：模拟 API 超时，返回可重试错误和 traceId；不编造正常答案。

## 5. 当天项目介绍产物

背景：让自建操作文档可问答且可追溯。目标：验证 Agent 工具闭环。关键决策：云 API、只读工具、有限循环、先关键词检索。难点：消息协议、引用校验、超时和成本。优化方向：按评测决定是否引入 embedding 与 pgvector。
